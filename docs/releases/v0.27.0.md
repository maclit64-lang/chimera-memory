# chimera-memory v0.27.0 — Final Large-Release Candidate

- **Source:** https://github.com/maclit64-lang/chimera-memory
- **PyPI:** not yet published — public PyPI currently serves `0.26.4`. This note
  describes the candidate prepared locally; it is not a live release.

This is the **final local release candidate** for the larger release. It
consolidates the full product stack built on top of the frozen v0.26.5
launch-polish line and bumps `chimera-memory` and `chimera-memory-types` together
(lockstep) from 0.26.5 to 0.27.0. No evidence-settlement scoring semantics
changed; no new evidence heuristics beyond those listed here.

## Classification

Minor release.

## What's new

### PR_EVIDENCE.md and GitHub Action

`chimera-memory xray generate` produces `PR_EVIDENCE.md` — the Merge X-Ray
receipt showing which claims settled against which checks at which declared
scope. `--format pr-comment` emits a concise PR-comment summary. A reusable
GitHub Action (`maclit64-lang/chimera-memory@v0.27.0`) runs the receipt on pull
requests and posts it as a comment / step summary / artifact.

### Evidence warning families

All warning families are **advisory review prompts** derived only from
already-recorded evidence and the change set. They flag weak, missing, or
risky evidence; they never prove the code is wrong or correct.

- **Evidence Quality Warnings** — `LINT_ONLY_EVIDENCE`, `ZERO_TESTS_COLLECTED`,
  `GREEN_ONLY_EVIDENCE`.
- **Test Integrity Warnings** — `TEST_SKIP_ADDED`, `TEST_XFAIL_ADDED`,
  `ONLY_FOCUS_ADDED`, `TEST_FILE_DELETED`.
- **Evidence Coverage Warnings** — `NO_TARGETED_EVIDENCE_FOR_CHANGED_SOURCE`.
- **Local Relapse Warnings** — `LOCAL_RELAPSE_WARNING`: a claim covering the
  current change resembles a *previously contradicted* local claim in the same
  ledger (overlapping scope plus the same normalized intent or a shared specific
  command fingerprint). Local-only and conservative — no cross-repo data, no
  prediction. They are review prompts, **not proof that a bug returned**, and
  never claim recurrence, correctness, or safety.

### Opt-in evidence gate

`chimera-memory xray generate --fail-on <policy>` and the Action's `fail-on`
input fail CI only when an explicit policy is not met. Default `never` (advisory
only — never fails). CLI policies:

`never`, `review-required`, `warnings`, `evidence-quality-warnings`,
`test-integrity-warnings`, `evidence-coverage-warnings`, `contradicted`,
`unsettled`, `scope-drift`, `evidence-dark`.

`warnings` aggregates all four warning families (evidence quality, test
integrity, evidence coverage, and local relapse), so `--fail-on warnings`
already covers local relapse warnings; there is no separate per-family CLI flag
for them. The gate enforces evidence policy and runs after the receipt, step
summary, artifact, and PR comment are produced.

### Proof Debt command

`chimera-memory proof-debt` (and `--json`) summarizes the local claims and
receipts that still need stronger evidence — unsettled/contradicted claims,
review-required receipts, local relapse signals, and the evidence
quality/test-integrity/evidence-coverage warning families — ordered by severity.
It is advisory and local-only, computed from the existing X-Ray result; it adds
no new analysis. See [../proof-debt.md](../proof-debt.md).

### Schema and trust boundary

The public X-Ray / `PR_EVIDENCE.md` JSON shape is locked by an additive schema
contract (`schema_version` = 1): required fields and counts stay present and
typed, while new fields (this release added `local_relapse_warnings`) are allowed
without breaking consumers. [../trust-and-redaction.md](../trust-and-redaction.md)
documents what is stored locally, what redaction is best-effort, and what the
receipt does and does not expose.

### Storage performance test hardening

The append performance guards were rewritten from brittle absolute wall-clock
budgets to load-tolerant **scaling** checks: they compare the per-append cost of
a late window against an early window, so they still catch an O(N²)/non-O(1)
append regression but do not fail merely because the host is under load. This is
a test-only change; storage behavior is unchanged.

## Honesty boundary

Chimera Memory scores evidence quality, not code correctness.

## What this does not prove

The receipt shows which claims settled against which checks at which declared
scope. It does **not** prove the code is correct, secure, or complete, it does
not rank or route models, and a Local Relapse Warning is **not** a statement that
any prior problem returned. Every warning is a review prompt. The receipt always
states what it does not prove.

## What did not change

- No correctness certification.
- No safety certification.
- No production-readiness claim.
- No cloud account or hosted service.
- No GitHub App.
- No cross-repo relapse or cross-repo memory.
- No model training, embeddings, or prediction.
- No Engine / Harness / Foundry / Authority / Mint work.
- No merge of the `court/crt-foundation` history.

## Relationship to v0.26.5

**v0.26.5** remains the frozen launch-polish RC (`python -m chimera_memory`,
verdict banner, duplicate-warning fix, the reusable GitHub Action /
Receipt-on-PR, and `--format pr-comment`) and is unchanged. **v0.27.0** supersets
it with the four warning families, the opt-in gate, the Proof Debt command, the
schema/trust lock, and the load-tolerant storage performance tests. Older tags
(`v0.26.4`, `v0.26.5`) are not force-moved.
