# chimera-memory v0.27.0 — Evidence Warnings + Opt-In CI Gate

- **PyPI:** https://pypi.org/project/chimera-memory/0.27.0/
- **Source:** https://github.com/maclit64-lang/chimera-memory

## Classification

Minor release candidate. This is the first release candidate to contain the full
product warning/gate stack on top of the v0.26.5 launch-polish line. It bumps
`chimera-memory` and `chimera-memory-types` together (lockstep) from 0.26.5 to
0.27.0. No evidence-settlement scoring semantics changed; no new evidence
heuristics beyond those listed below.

## What's new

### Evidence Quality Warnings

Advisory warnings derived from settled-claim command evidence:

- `LINT_ONLY_EVIDENCE` — source changed in scope, but only lint/static checks settled.
- `ZERO_TESTS_COLLECTED` — a test command ran but collected zero tests.
- `GREEN_ONLY_EVIDENCE` — bug-fix-like claim, all checks green, no targeted regression test.

### Test Integrity Warnings

Advisory warnings derived from the diff (added lines + deleted files):

- `TEST_SKIP_ADDED` — a skip marker was added to a test file.
- `TEST_XFAIL_ADDED` — an xfail marker was added.
- `ONLY_FOCUS_ADDED` — a focus-only marker (`it.only`, `fdescribe`, …) was added.
- `TEST_FILE_DELETED` — a test file was deleted.

### Evidence Coverage Warnings

- `NO_TARGETED_EVIDENCE_FOR_CHANGED_SOURCE` — source files changed but no settled
  command obviously targets them or nearby tests.

### Opt-In CI Evidence Gate

`chimera-memory xray generate --fail-on <policy>` and the Action's `fail-on`
input fail CI only when an explicit policy is not met. Default `never` (advisory
only — never fails). Policies:

`never`, `review-required`, `warnings`, `evidence-quality-warnings`,
`test-integrity-warnings`, `evidence-coverage-warnings`, `contradicted`,
`unsettled`, `scope-drift`, `evidence-dark`.

`warnings` aggregates all three warning categories. The gate enforces evidence
policy and runs so the receipt, step summary, artifact, and PR comment are
produced before any failure.

## Honesty

Chimera Memory scores evidence quality, not code correctness.

All warnings are **review prompts**. They do not prove the code is wrong or
correct. The receipt never claims code is correct, safe, production-ready,
certified, or approved to merge, and never says a test is "untested" or that an
agent lied. It always states what it does not prove.

## What did not change

- No correctness certification; no production-readiness claim.
- No cloud service; no GitHub App.
- No coverage instrumentation.
- No stale-evidence heuristic; no assertion-weakening heuristic; no
  test-count-dropped heuristic.
- No merge of the `court/crt-foundation` history.
- No release, publish, or tag was performed while preparing this candidate.

## Relationship to v0.26.5

- **v0.26.5** remains the frozen launch-polish RC (`python -m chimera_memory`,
  verdict banner, duplicate-warning fix, the reusable GitHub Action /
  Receipt-on-PR, and `--format pr-comment`). It is unchanged.
- **v0.27.0** is the stacked product RC: it builds on top of v0.26.5 and adds the
  warning categories and the opt-in CI gate above. It therefore supersets
  v0.26.5's content.
- An external release still depends on resolving the operator-side PyPI
  publish/credential issue. Until `v0.27.0` is tagged and published, pin the
  branch or a commit SHA for testing. Older tags (`v0.26.4`, `v0.26.5`) are not
  force-moved.
