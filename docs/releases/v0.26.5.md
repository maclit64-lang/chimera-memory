# chimera-memory v0.26.5 — Launch Polish + Reusable PR-Evidence Action

- **PyPI:** https://pypi.org/project/chimera-memory/0.26.5/
- **Source:** https://github.com/maclit64-lang/chimera-memory

## Classification

Patch release. Launch polish plus a new distribution surface (a reusable GitHub
Action). No evidence-settlement semantics changed. No M2B scoring/ranking/routing
added. No CI gate, no court-fork merge, no evidence-smell taxonomy port.

`chimera-memory` and `chimera-memory-types` are bumped together (lockstep) from
0.26.4 to 0.26.5; `chimera-memory-types` carries no functional change and is a
version-sync so the `chimera-memory-types>=0.26.5,<1.0` dependency stays
satisfiable.

## What's new

### CLI

- `python -m chimera_memory` now works as an entrypoint, equivalent to the
  `chimera-memory` console script (e.g. `python -m chimera_memory --help`).
- `chimera-memory xray generate --format pr-comment` emits a concise,
  reviewer-facing summary derived from the existing X-Ray verdict/counts. The
  full Markdown receipt is still written via `--output`.

### PR_EVIDENCE.md receipt

- The receipt now opens with an at-a-glance **verdict banner** (e.g. "Verdict:
  REVIEW REQUIRED"), derived from the existing verdict model — no new scoring.
- Fixed a duplicated working-tree-mode warning so the guidance appears once.

### Reusable GitHub Action / Receipt-on-PR

- A composite, repo-root `action.yml` installs Chimera Memory, generates
  `PR_EVIDENCE.md` for the pull-request diff, and surfaces it three ways: a
  sticky PR comment, a job step summary, and an uploaded artifact.
- Fork-safe: when the PR token is restricted, the comment step degrades to the
  step summary and artifact and never fails the job. Advisory only — the
  `fail-on` input defaults to `never` (no CI gate in this release).
- Example workflow: `docs/examples/github-actions/pr-evidence.yml`.

### Docs

- README hero sharpened so `PR_EVIDENCE.md` is unmistakably the main artifact,
  with a copy-paste Action section.
- Added `docs/release-action-readiness.md`: an Action-consumability checklist and
  a manual GitHub PR smoke protocol.

## Honesty

Chimera Memory scores **evidence quality, not code correctness**. Nothing in this
release claims code is correct, safe, production-ready, certified, or approved to
merge, or that an agent lied. The receipt reports weak / missing / contradicted /
unsettled / scope-drifted / evidence-dark signals and always states what it does
not prove.

## External-use requirement

Both must be released for outside repositories to consume this version:

- the `chimera-memory` / `chimera-memory-types` 0.26.5 packages on PyPI, and
- a `v0.26.5` Git tag (the first tag to include `action.yml`) on
  `maclit64-lang/chimera-memory`, which the Action examples reference as
  `@v0.26.5`.

Until the `v0.26.5` tag is pushed, pin the launch branch or a commit SHA for
pre-release testing (e.g. `maclit64-lang/chimera-memory@oss/memory-launch`). The
existing `v0.26.4` tag and its published package are left untouched.

## What did not change

- Settlement, claim-lock, MCP, hooks, and scoring logic unchanged.
- No CI gate / fail-on enforcement.
- No evidence-smell taxonomy port, no test-integrity detector, no relapse/
  proof-debt work.
- No merge of the `court/crt-foundation` history.
