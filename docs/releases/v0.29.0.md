# chimera-memory v0.29.0 — Agent Work Lifecycle

- **Source:** https://github.com/maclit64-lang/chimera-memory
- **PyPI:** not yet published — this note describes a candidate prepared locally;
  it is not a live release.

This is a **local release candidate**. It supersets the v0.28.0 line and bumps
`chimera-memory` and `chimera-memory-types` together (lockstep) from 0.28.0 to
0.29.0. No evidence-settlement scoring semantics changed; the new surfaces are
additive, local, and advisory.

## Classification

Minor release.

## Theme

Where v0.28.0 added **local operational memory** (how agents worked) and ways to
package and review it, v0.29.0 adds a **local agent work lifecycle**: the task an
agent was asked to do, the context it starts with, the lifecycle envelope it
records work against, and the review it leaves behind for the next agent.
Everything in this release is **local agent lifecycle context**: advisory only,
read-only on read paths, and explicit/append-only where it captures new data.
None of it is a correctness, safety, approval, merge, or production-readiness
signal, and none of it is a form of verification.

## What's new

### Agent Work Brief

A local **input contract** that captures the *requested task* before work starts:
objective, in-scope and out-of-scope paths, constraints, checks to report, done
criteria, and context links. `work-brief add` is an explicit append-only write;
`work-brief list` / `show` are read-only and never create a store. A brief states
what was asked — it is not an output verdict.

### Branch Primer and Agent Kickoff Pack

`branch-primer` composes existing projections (the Work Packet plus an optional
review-thread delta, and an optional brief) into one concise, pasteable
**starting-context** summary: what to read before beginning. `branch-primer
bundle` writes a portable **Agent Kickoff Pack** (primer + prompt header + brief
files + manifest) into a directory you name. Read-only except the bundle you
write.

### Agent Work Session

An **event-sourced lifecycle envelope** tying one task to the brief that started
it, the review thread / kickoff context used, and the snapshots and artifacts
attached for review. Events append to `.chimera-memory/work_session_events.jsonl`
and fold into a read-only projection with neutral statuses (`open`, `blocked`,
`closed`, `unknown`). `work-session start/attach-snapshot/attach-artifact/close`
and the closeout reporting commands (`report-check`, `report-done`,
`note-carryover`) are explicit CLI writes; `list` / `show` are read-only.

### Session Closeout Pack

`work-session closeout` composes an end-of-session summary: session state, the
original brief, a **local first-vs-latest snapshot comparison** of attached
snapshots, the checks the agent *reported* running, the done-criteria it
*reported* observing, attached artifacts, and carryover for the next agent.
`work-session closeout-bundle` writes a portable, hash-manifested bundle. Reported
checks are not executed here; done observations carry a neutral status, never a
verdict.

### Session Review Rollup / Carryover Inbox

`work-session rollup` is a **read-only review board across sessions**: which
sessions are open, blocked, or recently closed, the checks agents reported, the
done observations they recorded, the **carryover inbox**, and suggested review
targets. `work-session rollup-bundle` writes a portable bundle. Exact filters
(`--status`, `--tag`, `--carryover-tag`); limits apply after filters and the
carryover inbox is a view, never an automatic task queue or router.

### Agent Context Doctor

`context-doctor` is a local **context-hygiene report**: advisory *findings* about
missing, stale, or incomplete session context before another agent continues —
open sessions with no closeout events, blocked sessions with carryover, sessions
without snapshots or reported checks, briefs not linked to a session, and
explicitly referenced review-thread / kickoff-pack directories missing on disk.
Findings use a `kind` only — no severity, ranking, or score — and nothing is
executed. `context-doctor bundle` writes a portable bundle.

### MCP surfaces (read-only) and CLI-only writes

The local MCP server exposes the new lifecycle **read views** without extra flags:
`chimera_work_brief_list` / `_show`, `chimera_work_session_list` / `_show` /
`_closeout` / `_rollup`, `chimera_branch_primer` / `_prompt_header`, and
`chimera_context_doctor`. Read tools never create or mutate a store and execute
nothing. Every write, lifecycle, and bundle-export operation (`work-brief add`,
`work-session` writes and reporting, and all `*-bundle` writers) stays
**CLI-only** and is not exposed via MCP — consistent with the existing
write/execute gating.

## Honesty boundary

The v0.29 surfaces record and review **local agent lifecycle context**. Briefs,
primers, sessions, closeouts, rollups, the carryover inbox, and context-hygiene
findings are **advisory** — they help an agent or reviewer remember, inspect, and
hand off local work. They are not a correctness, safety, approval, merge, or
production-readiness signal, and not a form of verification. Statuses and findings
are neutral observations, never verdicts. User-authored text (brief fields,
carryover notes) is recorded verbatim; the tool's own generated wording stays
neutral.

## Migration and compatibility

- Additive only. Existing ledger files, claims, outcomes, scores, the X-Ray /
  `PR_EVIDENCE.md` JSON contract, and the v0.28 operational-memory surfaces are
  unchanged.
- New local artifacts live in their own files: work briefs in
  `.chimera-memory/work_briefs.jsonl`, work-session events in
  `.chimera-memory/work_session_events.jsonl`; kickoff / closeout / rollup /
  context-doctor bundles are written only to directories you name explicitly.
- New CLI commands (`work-brief`, `work-session` and its closeout / rollup
  subcommands, `branch-primer`, `context-doctor`) are additive; existing commands
  and their output shapes are preserved.
- `chimera-memory` and `chimera-memory-types` move together to 0.29.0; the
  inter-package dependency floor tracks the same line
  (`chimera-memory-types>=0.29.0,<1.0`).

## What did not change / non-goals

- No correctness, safety, or production-readiness certification.
- No automatic Work Brief or Work Session creation; no automatic check execution,
  agent run, prompt injection, tool execution, agent spawning, or workflow launch.
- No scoring, ranking, priority or severity ordering, routing, trust score, or
  verdict (correctness / safety / approval / merge / production-readiness).
- No fuzzy / semantic / model-based matching; filters are exact-match.
- No cloud account, hosted service, cross-repo memory, embeddings, or prediction.
- No merge of the `court/crt-foundation` history.
