# chimera-memory v0.30.0 — Harness Lite

- **Source:** https://github.com/maclit64-lang/chimera-memory
- **PyPI:** not yet published — this note describes a candidate prepared locally;
  it is not a live release.

This is a **local release candidate**. It supersets the v0.29.0 line and bumps
`chimera-memory` and `chimera-memory-types` together (lockstep) from 0.29.0 to
0.30.0. No evidence-settlement scoring semantics changed; the new surfaces are
additive, local, and advisory.

## Classification

Minor release.

## Theme

Where v0.29.0 added a **local agent work lifecycle**, v0.30.0 adds **Harness Lite**:
a local run-observation ledger and bridge. It records what a command/check/tool
invocation was, where and when it ran, the exit code if known, and bounded,
redacted output previews — and surfaces those observations across the lifecycle.
It is not an autonomous execution platform, not a correctness engine, not a merge
gate, and not a task router. An **exit code is recorded, not interpreted as a
verdict**; statuses are neutral (`completed` / `interrupted` / `unknown`).

## What's new

### HarnessRun model and append-only ledger

A `HarnessRun` is a local observation appended to `.chimera-memory/harness_runs.jsonl`
(append-only; reading never creates a store). Each run records mode, command, cwd,
exit code (`0` / nonzero / null), neutral status, bounded stdout/stderr previews,
output hashes, redaction/truncation flags, attached artifacts, work-session id,
brief id, check label, note, tags, and source.

### `harness record` / `run` / `list` / `show`

- **`record`** registers a command that ran *elsewhere* — Chimera executes nothing.
- **`run`** explicitly runs a local command *once*, in the foreground, **only because
  you invoked `harness run`** — never automatic, never background. It captures the
  exit code, duration, and bounded previews; the full captured stdout/stderr is
  sha256-hashed (not stored). Recording the observation exits the Chimera process
  `0`; the observed command's own exit code is stored in `run.exit_code`.
- **`list`** / **`show`** are read-only and never create a store.

Outputs are bounded (default 4096-byte previews; `--max-output-bytes` override),
`output_truncated` marks over-limit output, and previews are sent through the local
redaction helper with `redaction_applied` set when a secret-like pattern is replaced.

### Lifecycle integration (read-only)

Run observations surface wherever the next agent starts or a reviewer inspects:
`work-session runs`; the **Session Closeout** (`harness_runs[]` + markdown section);
the **Session Rollup** (`harness_run_count` / `executed` / `recorded` counts +
`recent_harness_runs`); the **Context Doctor** (advisory findings
`session_without_harness_runs`, `harness_run_without_session`,
`harness_run_output_truncated`, `harness_run_with_redacted_preview`); the **Branch
Primer** (`harness_runs` + a "Harness run observations" section + a `harness list`
first-read); the **Agent Kickoff Pack** (`HARNESS_RUNS.md` + `harness-runs.json`,
hashed in the manifest); the **Work Packet** (`harness_runs` + counts, `--session`
narrowing, `--limit-harness-runs`); the **Work Packet diff** (`harness_runs`
added/removed by run id); and an advisory **`harness candidates`** projection
(conservative, mostly verbatim from each run's note/check label, never saved
automatically — review before saving a Tool Note).

### MCP read surfaces

The local MCP server exposes read-only tools `chimera_harness_run_list`,
`chimera_harness_run_show`, and `chimera_harness_run_candidates` without extra
flags; the existing `chimera_work_packet` read tool now carries harness fields.
Read tools never create or mutate a store and execute nothing.

## Honesty boundary

Harness Lite records and reviews **local run observations**. An exit code is data,
not a judgment: exit code `0` and a nonzero exit code are recorded as observations,
never labelled outcomes. Nothing here approves, certifies, scores, ranks, routes,
or judges work, and none of it is a correctness, safety, approval, merge, or
production-readiness signal. User-authored command/note text is preserved verbatim;
the tool's own generated wording stays neutral.

## Migration and compatibility

- Additive only. Existing ledger files, claims, outcomes, scores, the X-Ray /
  `PR_EVIDENCE.md` JSON contract, and the v0.28/v0.29 surfaces are unchanged.
- A new local file holds harness observations: `.chimera-memory/harness_runs.jsonl`.
  It changes only on `harness record` / `harness run`; every read surface leaves it
  and the work-session event ledger unchanged.
- Closeout (`harness_runs`), Rollup (harness counts + `recent_harness_runs`), Work
  Packet (`harness_runs` + counts + `limit_harness_runs` filter), Branch Primer
  (`harness_runs`), the packet diff (`harness_runs`), and the Context Doctor (new
  finding kinds) gained **additive** keys only; existing output shapes are preserved.
- New CLI surfaces (`harness record/run/list/show/candidates`, `work-session runs`,
  `branch-primer bundle` harness files, `work-packet --limit-harness-runs`) are
  additive.
- `chimera-memory` and `chimera-memory-types` move together to 0.30.0; the
  inter-package dependency floor tracks the same line
  (`chimera-memory-types>=0.30.0,<1.0`).

## What did not change / non-goals

- No automatic, scheduled, or background command execution; `harness run` runs once
  in the foreground only when invoked.
- No agent spawning, workflow launch, routing, scoring, ranking, trust score,
  certification, or any verdict (correctness / safety / approval / merge /
  production-readiness); an exit code is recorded, never interpreted as an outcome label.
- No fuzzy / semantic / model-based matching; no automatic Tool Note save (the
  `harness candidates` projection is review-gated).
- No MCP write/run/record surface; write operations stay CLI-only and explicit.
- No cloud account, hosted service, cross-repo memory, embeddings, or prediction.
- No merge of the `court/crt-foundation` history.
