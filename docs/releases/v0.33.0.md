# chimera-memory v0.33.0 — Memory Evidence Bridge

- **Source:** https://github.com/maclit64-lang/chimera-memory
- **PyPI:** not yet published — this note describes a candidate prepared locally;
  it is not a live release.

This is a **local release candidate**. It supersets the v0.32.0 line and bumps
`chimera-memory` and `chimera-memory-types` together (lockstep) from 0.32.0 to
0.33.0. No evidence-settlement scoring semantics changed; the new surfaces are
additive, local, and read-only.

## Classification

Minor release.

## Theme

Where v0.30.0–v0.32.0 added Harness Lite, the portable Harness Evidence Bundle,
and the Consequence Observation Ledger, v0.33.0 adds the **Memory Evidence Bridge**
scaffold: a read-only layer that consumes *exported* Memory artifacts and
normalizes them into a stable, neutral input record (`memory_bridge_evidence.v1`)
by reading the on-disk artifact contract. It defines the consumption contract a
future, clean Engine/Harness branch can adopt — without importing Memory
internals. It decides nothing.

## What's new

### Normalized evidence record (`memory_bridge_evidence.v1`)

`bridge normalize` emits one record per bundle: `schema_version`, `created_at`,
`source_kind`, `source_path`, `source_manifest_sha256`, `memory_version`,
`work_session_id`, `brief_id`, normalized `harness_runs[]` (observed fields only),
`consequence_observations[]`, `suggested_checks[]`, `artifact_refs[]`, a `manifest`
check (counts), `notes[]`, and — for Work Packets — a `work_packet_reference`
object. Unknown input fields are ignored deterministically.

### `bridge inspect` and `bridge normalize`

- `chimera-memory bridge inspect --bundle-dir DIR [--json]` reads a bundle and
  reports neutral counts: the manifest check (`file_count`, `hash_mismatch_count`,
  `missing_file_count`, `unexpected_store_file_count`, `parse_error_count`,
  `recognized_record_count`) plus `harness_run_count`,
  `consequence_observation_count`, `suggested_check_count`, and
  `artifact_ref_count`.
- `chimera-memory bridge normalize --bundle-dir DIR --output-json FILE` writes the
  full record to the explicit output path only.

### Readers

- **Harness Evidence Bundle** reader: normalizes `harness-evidence.json` runs into
  observed fields (`run_id`, `mode`, `command`, `cwd`, `exit_code`, `status`,
  `check_label`, `redaction_applied`, `output_truncated`, `stdout_sha256`,
  `stderr_sha256`, `artifact_refs`).
- **Work Packet bundle** reader: normalizes the packet's embedded `harness_runs`
  and `consequence_observations`, aggregates suggested checks, and resolves a
  `harness_evidence_bundle` reference. Resolution tries the packet directory, then
  its parent (the common output root for sibling bundles), then the path as given,
  and carries the referenced bundle's `manifest_sha256` and `harness_run_count`. A
  missing or unresolvable reference increments `missing_file_count` (or
  `parse_error_count`) and adds a neutral note rather than raising.

### Manifest hash checking and tamper detection

For every file listed in a bundle's `manifest.json`, the bridge recomputes the
`sha256` and compares it to the recorded hash. A bundle whose files match reports
`hash_mismatch_count` 0; a file altered after the bundle was written increments
`hash_mismatch_count`. Tamper detection is reported as a **count, not a verdict**;
the bridge reports a hash mismatch count rather than any judgment on the manifest. A
mutable store file (`*.jsonl`, a `.chimera-memory` directory) inside a portable
bundle is counted as `unexpected_store_file_count`.

### Read-only MCP surfaces

`chimera_memory_bridge_inspect` (counts) and `chimera_memory_bridge_normalize_preview`
(the full record returned inline, no file written) are available without extra
flags. The normalize *writer* (`bridge normalize --output-json`) is intentionally
CLI-only and not exposed through MCP.

## Honesty boundary

The bridge answers what was observed; it never answers whether work was correct,
complete, appropriate to merge, or which candidate is best. An exit code is carried
as observed data (exit code 0 is not labelled an outcome, and a nonzero exit code
is not either). The bridge does not grade or rank evidence, route candidates, grant
authority, or create training data; consuming a normalized record confers none of
those. User-authored command / note / check text is preserved verbatim; the
bridge's own generated wording stays neutral.

## Storage and read-only invariants

- `bridge inspect` and `bridge normalize` read files only; they do not mutate the
  source bundle, do not create or mutate a `.chimera-memory` store, execute
  nothing, and trigger no scan.
- `normalize` writes only to the explicit `--output-json` path.
- The bridge reads the on-disk artifact contract; it does **not** depend on a live
  `.chimera-memory` store.

## Engine repo

The Engine repo was **not** touched. The Engine-side integration remains deferred
until a clean, authorized Engine/Harness base exists; this release prepares the
handoff by defining the `memory_bridge_evidence.v1` contract and the on-disk reader
behavior that a future Engine branch can adopt without importing Memory internals.

## Migration and compatibility

- Additive only. Existing ledgers, claims, outcomes, scores, the X-Ray /
  `PR_EVIDENCE.md` JSON contract, and the v0.28–v0.32 surfaces are unchanged.
- New CLI surfaces (`bridge inspect` / `bridge normalize`) and two read-only MCP
  tools are additive; no existing output shape changed.
- `chimera-memory` and `chimera-memory-types` move together to 0.33.0; the
  inter-package dependency floor tracks the same line
  (`chimera-memory-types>=0.33.0,<1.0`).

## What did not change / non-goals

- No automatic scan, automatic or background command execution, routing, ranking,
  trust grade, certification, or any verdict (correctness / safety / approval /
  merge / production-readiness); no outcome-label interpretation of exit codes; no
  grading or ordering of importance.
- No training / Foundry / Forge export, Engine import, network upload, cloud sync,
  or GitHub Action.
- No MCP write/export surface and no MCP normalize writer.
- No Engine repo changes; no work based on the `court/crt-foundation` lane.
- No merge of the `court/crt-foundation` history.
