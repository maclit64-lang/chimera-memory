# chimera-memory v0.32.0 — Consequence Observation Ledger

- **Source:** https://github.com/maclit64-lang/chimera-memory
- **PyPI:** not yet published — this note describes a candidate prepared locally;
  it is not a live release.

This is a **local release candidate**. It supersets the v0.31.0 line and bumps
`chimera-memory` and `chimera-memory-types` together (lockstep) from 0.31.0 to
0.32.0. No evidence-settlement scoring semantics changed; the new surfaces are
additive, local, and advisory.

## Classification

Minor release.

## Theme

Where v0.30.0 added **Harness Lite** and v0.31.0 added the portable **Harness
Evidence Bundle**, v0.32.0 adds the **Consequence Observation Ledger v0**: a local,
append-only, neutral layer that an explicit scan derives from existing
Memory/Harness evidence. It records *inspection targets* — a work session with no
linked harness observations, a harness run that recorded a nonzero exit code, a
truncated or redacted preview, or a reported check with no matching run — together
with suggested checks. It is an **inspection-target ledger, not a gate**, and the
next bridge from Memory/Harness toward a future Engine/Harness/Forge loop.

## What's new

### Consequence Observation model (`consequence_observation.v1`)

A consequence observation is appended to `.chimera-memory/consequence_observations.jsonl`
(append-only; reading never creates a store). Each record carries `observation_id`,
`created_at`, `source` (`{kind: "scan", scan_id, package, version}`), `subject`
(`{type, id}`), `observation_kind`, `affected_paths`, `evidence_refs`,
`suggested_checks`, `note`, `tags`, `work_session_id`, `brief_id`,
`harness_run_ids`, and `bundle_ids`. The `observation_id` (`co_<sha256>`) is
derived from the `schema_version`, `observation_kind`, `subject`, `evidence_refs`,
and `suggested_checks`, so re-scanning the same evidence produces the same id.

### Explicit scan, with a dry run

- `consequence scan` reads the local work-session, work-brief, and harness ledgers
  and records neutral observations. It is the only write path; it executes nothing
  and never mutates `harness_runs.jsonl` or `work_session_events.jsonl`.
- `consequence scan --dry-run` previews the observations a scan would record
  without writing anything.
- De-duplication is deterministic: a scan appends an observation only when its
  `observation_id` is not already present, so re-scanning records nothing new.
- Filters: `--work-session` / `--brief` / `--tag` / `--limit`; `--json` for
  machine-readable output.

### Conservative v0 scan rules

- **session_without_harness_runs** — a work session has no linked harness runs;
  suggested checks come from the Work Brief when available.
- **harness_run_nonzero_exit_code_observed** — a harness run recorded a nonzero
  exit code (recorded, not interpreted).
- **harness_run_output_truncated** — a run's output preview was truncated.
- **harness_run_preview_redacted** — a run's preview had redaction applied.
- **reported_check_without_matching_harness_run** — a session reported a check
  with no harness run whose check label or command matches (literal match only;
  no fuzzy or model-based matching).

A `work_packet_references_harness_evidence_bundle` rule is **deferred**: work
packets are generated artifacts rather than store state, so it cannot be
discovered cleanly from the local ledgers alone.

### List, show, and the session view

`consequence list` (with `--work-session` / `--brief` / `--kind` / `--tag` /
`--limit` / `--json`) and `consequence show OBSERVATION_ID` are read-only and never
create or mutate a store. `work-session consequences SESSION_ID` lists the
observations attached to one session.

### Lifecycle integration (already-recorded only; never auto-scans)

Recorded observations surface read-only across the review surfaces, which **never
trigger a scan**:

- **Session Closeout** — a compact `consequence_observations` array plus a
  `## Consequence observations` markdown section.
- **Session Rollup** — a `consequence_observation_count` summary field plus
  `recent_consequence_observations`.
- **Work Packet** — a compact `consequence_observations` array, a
  `consequence_observation_count` summary field, and a markdown section
  (`--session` narrows them).
- **Context Doctor** — an advisory `consequence_observation_without_session`
  finding when an observation is not attached to a known work session.

### Read-only MCP tools

The local MCP server exposes `chimera_consequence_observation_list` and
`chimera_consequence_observation_show` without extra flags. They never create or
mutate a store and execute nothing. **Scan is not exposed through MCP** — recording
observations stays CLI-only.

## Honesty boundary

A consequence observation is a neutral inspection target. It does not say work is
correct, complete, or appropriate to merge; it does not rank or grade observations
and attaches no ordering of importance; it never interprets a nonzero exit code as
a judgment (an exit code is recorded, not labelled); it routes nothing, approves
nothing, and executes nothing. User-authored command / note / check text is
preserved verbatim; the tool's own generated wording stays neutral.

## Storage and write boundary

- Read-only on the memory store on every read path; `consequence_observations.jsonl`
  changes only on `consequence scan` without `--dry-run`.
- A scan reads the existing ledgers and writes only the consequence ledger; it
  never mutates `harness_runs.jsonl` or `work_session_events.jsonl`, executes
  nothing, and creates no Work Briefs, Work Sessions, Closeouts, or Tool Notes.
- Closeout, rollup, work packet, and context doctor surface already-recorded
  observations only — they never auto-scan.

## Migration and compatibility

- Additive only. Existing ledgers, claims, outcomes, scores, the X-Ray /
  `PR_EVIDENCE.md` JSON contract, and the v0.28–v0.31 surfaces are unchanged.
- A new local file holds observations: `.chimera-memory/consequence_observations.jsonl`.
- Closeout, Rollup, and Work Packet gained **additive** keys only
  (`consequence_observations` / `consequence_observation_count` /
  `recent_consequence_observations`); existing output shapes are preserved. The
  Context Doctor gained one additive finding kind.
- New CLI surfaces (`consequence scan` / `list` / `show`, `work-session
  consequences`) and two read-only MCP tools are additive.
- `chimera-memory` and `chimera-memory-types` move together to 0.32.0; the
  inter-package dependency floor tracks the same line
  (`chimera-memory-types>=0.32.0,<1.0`).

## What did not change / non-goals

- No automatic scan during closeout / rollup / work-packet; no automatic or
  background command execution.
- No routing, ranking, trust grade, certification, or any verdict (correctness /
  safety / approval / merge / production-readiness); no outcome-label interpretation
  of exit codes; no grading or ordering of importance.
- No training / Foundry / Forge export, Engine import, network upload, cloud sync,
  or GitHub Action.
- No MCP scan/write surface; recording observations stays CLI-only.
- No automatic Tool Note save; no semantic / model-based matching; no
  model-generated lessons.
- No merge of the `court/crt-foundation` history.
