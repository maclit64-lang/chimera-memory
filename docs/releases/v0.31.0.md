# chimera-memory v0.31.0 — Harness Evidence Bundle

- **Source:** https://github.com/maclit64-lang/chimera-memory
- **PyPI:** not yet published — this note describes a candidate prepared locally;
  it is not a live release.

This is a **local release candidate**. It supersets the v0.30.0 line and bumps
`chimera-memory` and `chimera-memory-types` together (lockstep) from 0.30.0 to
0.31.0. No evidence-settlement scoring semantics changed; the new surfaces are
additive, local, and advisory.

## Classification

Minor release.

## Theme

Where v0.30.0 added **Harness Lite** (a local run-observation ledger), v0.31.0
adds the **Harness Evidence Bundle**: a portable, redacted, hash-manifested
*export* of those observations that external Chimera Engine / Harness / Forge
tooling can consume as a neutral observation artifact — without importing
`chimera-memory`. It is an evidence transport format, not a verdict engine. An
exit code is recorded, never interpreted; statuses are neutral (`completed` /
`interrupted` / `unknown`).

## What's new

### Portable Harness Evidence Bundle (`harness_evidence_bundle.v1`)

`chimera-memory harness bundle --work-session SESSION_ID --output-dir DIR` writes
a five-file bundle:

- `HARNESS_EVIDENCE.md` — a human-readable overview.
- `harness-evidence.json` — the machine-readable bundle: `schema_version`,
  `bundle_id`, `created_at`, `root`, `filters`, `source`, `summary`,
  `harness_runs`, `redaction_summary`.
- `harness-runs.json` — just the portable run array, for external tools.
- `manifest.json` — every other file with its `sha256` and byte count.
- `README.md` — a short description for whoever receives the bundle.

The `bundle_id` is content-derived (`heb_<sha256-of-runs>`), so the same runs
produce the same id. File ordering and JSON are deterministic (`sort_keys`), and
the manifest records a `sha256` and byte size for each generated file.

### Compact, output-bounded run records

Each run is projected to a compact, output-free record (`run_id`, timestamps,
`duration_ms`, `mode`, `command`, `cwd`, `exit_code`, `status`, `check_label`,
`note`, `tags`, `work_session_id`, `brief_id`, `redaction_applied`,
`output_truncated`, `stdout_sha256`, `stderr_sha256`, `artifact_refs`, `source`).
Full stdout/stderr is **omitted**; outputs are referenced by `sha256`. Bounded,
already-redacted previews are **omitted by default** and included only with
`--include-previews`, so a portable bundle is attachable to a review by default.
A `redaction_summary` records `redacted_preview_count`, `truncated_output_count`,
and whether previews were included.

### Inspect and diff

- `harness bundle-inspect DIR [--json]` recomputes each manifest hash and reports
  neutral counts: `file_count`, `harness_run_count`, `hash_mismatch_count`,
  `missing_file_count`, `unexpected_store_file_count`, plus whether the
  `schema_version` is recognized and the runs parse. It flags any mutable store
  file (`*.jsonl`, a `.chimera-memory` directory) that should never be inside a
  portable bundle.
- `harness bundle-diff LEFT RIGHT [--json]` reports added / removed `run_id`s,
  summary deltas (including redaction / truncation / artifact-ref deltas), and
  changed manifest files. Because the ledger is append-only, a run's content
  should not change; the diff defensively reports `content_changed` for any
  `run_id` present in both bundles with a different content hash. `content_changed`
  is a signal to inspect, not a claim of corruption.

### Session and packet surfaces

- `work-session harness-bundle SESSION_ID --output-dir DIR` writes a bundle scoped
  to a session via the same writer; it does not close the session or write a
  closeout.
- `work-packet bundle --session SESSION_ID --output-dir packet
  --harness-evidence-dir DIR` records a `harness_evidence_bundle` reference
  (`path`, `schema_version`, `manifest_sha256`, `harness_run_count`) in the packet
  JSON plus a markdown section. The packet references by relative path and manifest
  hash; it never copies the evidence bundle and never auto-generates one.

### Read-only MCP surfaces

The local MCP server exposes two read-only tools without extra flags:
`chimera_harness_bundle_inspect` and `chimera_harness_bundle_diff`. They inspect
and compare existing bundles; they never create or mutate a store and execute
nothing.

## Honesty boundary

The bundle records and transports **local run observations**. An exit code is
data, not a judgment: exit code `0` and a nonzero exit code are recorded as
observations, never labelled outcomes. Nothing here approves, certifies, scores,
ranks, routes, or judges work, and none of it is a correctness, safety, approval,
merge, or production-readiness signal. Consuming a bundle confers no scoring,
routing, training, or execution authority. User-authored command / note / check
text is preserved verbatim; the tool's own generated wording stays neutral.

## Storage and write boundary

- Read-only on the memory store: building, inspecting, and diffing bundles read
  the ledger and write nothing to it; `harness_runs.jsonl` changes only on
  `harness record` / `harness run`.
- Explicit write only into the chosen output directory; bundle writing executes
  nothing and creates no harness runs or work-session events.
- Bundle creation is **CLI-only**. The MCP server exposes inspect/diff (read-only)
  but never bundle creation, and never `harness record` / `harness run`.

## External consumption boundary

A bundle is a plain directory of JSON + markdown with a `sha256` manifest. An
external tool can read `harness-runs.json` (or `harness-evidence.json`) and verify
integrity by recomputing the `manifest.json` hashes — in any language, without
importing `chimera-memory`. The bundle carries local observations only.

## Migration and compatibility

- Additive only. Existing ledgers, claims, outcomes, scores, the X-Ray /
  `PR_EVIDENCE.md` JSON contract, and the v0.28/v0.29/v0.30 surfaces are unchanged.
- The Work Packet core shape is unchanged: the `harness_evidence_bundle` reference
  appears in a packet bundle only when `--harness-evidence-dir` is supplied.
- New CLI surfaces (`harness bundle` / `bundle-inspect` / `bundle-diff`,
  `work-session harness-bundle`, `work-packet bundle --harness-evidence-dir`) and
  two read-only MCP tools are additive.
- `chimera-memory` and `chimera-memory-types` move together to 0.31.0; the
  inter-package dependency floor tracks the same line
  (`chimera-memory-types>=0.31.0,<1.0`).

## What did not change / non-goals

- No automatic, scheduled, or background execution; no agent spawning, workflow
  launch, routing, scoring, ranking, trust score, certification, or any verdict
  (correctness / safety / approval / merge / production-readiness); no outcome-label
  interpretation of exit codes.
- No training / Foundry / Forge export, Engine import, network upload, cloud sync,
  or GitHub Action.
- No MCP write/export surface and no MCP bundle creation; write operations stay
  CLI-only.
- No automatic Tool Note save, no semantic / model-based matching, no
  model-generated lessons.
- No merge of the `court/crt-foundation` history.
