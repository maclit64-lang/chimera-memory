# Agent Work Lifecycle (v0.29)

The v0.29 surfaces are a set of local, advisory **operational-memory** tools for an AI coding
agent's work lifecycle — from the task it was asked to do, through the context it starts with, to
the review left behind for the next agent. Everything here is local-first and advisory: none of it
is a correctness, safety, approval, merge, or production-readiness signal, and none of it runs an
agent, executes checks, scores, ranks, routes, or syncs.

## The lifecycle

| Stage | Surface | What it is |
|---|---|---|
| Requested task | **Work Brief** | The kickoff *input contract* — objective, scope, constraints, checks to report, done criteria. See [work-brief.md](work-brief.md). |
| Starting context | **Branch Primer** | What to read *before* starting — work state + operational memory + an optional review-thread delta. See [branch-primer.md](branch-primer.md). |
| Portable pre-work | **Agent Kickoff Pack** | The primer + brief + prompt header written as one portable, hash-manifested bundle (`branch-primer bundle`). See [branch-primer.md](branch-primer.md). |
| Lifecycle envelope | **Work Session** | An event-sourced envelope tying a brief, review thread, attached snapshots, and artifacts to one task; neutral statuses (open/blocked/closed/unknown). See [work-session.md](work-session.md). |
| Post-work closeout | **Session Closeout Pack** | An end-of-session summary — session state, original brief, a local first-vs-latest snapshot comparison, reported checks, done observations, and carryover. See [work-session.md](work-session.md). |
| Multi-session review | **Session Rollup / Carryover Inbox** | A read-only board across sessions — open / blocked / recently closed work, reported checks, done observations, and the carryover inbox. See [work-session.md](work-session.md). |
| Context hygiene | **Context Doctor** | Advisory findings about missing, stale, or incomplete context before another agent continues. See [context-doctor.md](context-doctor.md). |

## How they fit together

```
work-brief ──▶ branch-primer ──▶ kickoff-pack ──▶ work-session ──▶ session closeout
 (the task)     (what to read)     (portable)      (+ thread snapshots)   (post-work)
                                                          │
                                                          ├──▶ session rollup   (across sessions)
                                                          └──▶ context-doctor   (hygiene findings)
```

A Work Brief states *what was asked*; the Branch Primer and Kickoff Pack describe *what to read
first*; the Work Session records *what happened*; and the Closeout, Rollup, and Context Doctor are
*review views* over that recorded work. Each surface references the others rather than duplicating
them.

## Shared properties

- **Local-first.** Everything lives under `.chimera-memory/` (the event ledger) or in explicit
  output files/directories you name. No cloud, no sync, no account.
- **Read-only by default.** Listing, showing, closeout, rollup, and context-doctor read the ledger
  and write nothing; on an absent store they are simply empty and create no store. Writes
  (`work-brief add`, `work-session start/attach/close/report-*/note-carryover`) are explicit and
  append-only to their own event file. User-authored text is recorded verbatim.
- **Portable bundles.** Kickoff, closeout, rollup, and context-doctor each export a directory
  bundle with a `manifest.json` carrying sha256 + byte sizes; bundles refuse a non-empty output
  directory without `--force` and write only into the directory you name.
- **Read-only MCP.** The read views are exposed as read-only MCP tools (available without
  `--allow-write`); every write, lifecycle, and bundle operation stays CLI-only.
- **Exact and deterministic.** Filters are exact-match (no fuzzy / semantic matching), order is
  deterministic, and limits apply after filters.

## Harness Lite (v0.30)

v0.30 adds **Harness Lite**, a local run-observation ledger that threads through this lifecycle.
A harness run records what a command/check was (or, with `harness run`, is explicitly run locally),
its exit code, and bounded redacted output previews — attached to a Work Session. An exit code is
recorded, not interpreted as a verdict. Run observations then surface across the lifecycle: in the
Branch Primer and Kickoff Pack (`HARNESS_RUNS.md` / `harness-runs.json`), the Work Packet (with
counts and a packet diff of added/removed runs), the Session Closeout and Rollup, the Context
Doctor (advisory findings), an advisory `harness candidates` projection, and read-only MCP tools.
Write surfaces (`harness record` / `harness run`) are explicit and CLI-only; every read surface
reads the ledger and writes nothing. See [harness-lite.md](harness-lite.md). Run observations can
also be exported as a portable, hash-manifested
[Harness Evidence Bundle](harness-evidence-bundle.md) for external tooling.

An explicit [consequence scan](consequence-observations.md) can then read this Memory/Harness
evidence and record neutral, append-only inspection targets (an inspection-target ledger, not a
gate); recorded observations surface read-only in the closeout, rollup, work packet, and context
doctor.

## Non-goals

The v0.29 surfaces do not run an agent, inject prompts, execute checks, spawn agents, launch
workflows, route work, score, rank, prioritize, or sync. Statuses and findings are neutral
observations, never verdicts — they do not approve, certify, or judge the work.
